## The loop

```
/loop /ship PROJ-123
```

```
                    ┌── fix round (max 3 per area, counter on disk) ──┐
                    ↓                                                 │
implement (agent) → verify.sh → VERDICT: FAIL → route by area → fix ──┘
                       │             └→ CAUSE: <no-retry> → stop, write stop record
                       │
                  VERDICT: PASS → next area → full tier → draft PR
                                                             │
                                  ┌── round 2 (max) ─────────┤
                                  ↓                          ↓
                           fix (owning agent) ← /pr-self-check: review the diff
                                  │              against this project's own skills
                                  └→ re-verify → push → report → stop
```

Three of the stages loop, each with a different stop condition. **Implement** and
**self-check** are goal-based — repeat until a verifiable condition holds,
bounded by a hard cap. **Watch** is time-based. The
drift check is not a stage at all: it cuts across every boundary and aborts the
whole run.

### One stage per invocation

`/ship` runs exactly one stage and ends the turn, re-arming itself with
`ScheduleWakeup`. A full run in one context is both the most expensive context
here and the one most likely to compact halfway through — and a compact
mid-stage loses the attempt counters with everything else. One stage per
invocation makes every stage a fresh context by construction.

For the same reason **every counter lives in the state file, never in the
model's head**. A counter you cannot read back after a compact is not a cap.

### Workflow skills

| Command | Purpose |
|---|---|
| `/create-task "<description>"` | draft a Jira task, get it approved, create it |
| `/plan-task <id\|"description">` | explore, write the plan, seed the state |
| `/implement-plan <id>` | dispatch the agents, verify and fix per area |
| `/verify-change [tier] [scope]` | **the definition of done** — the only thing that decides |
| `/self-check [id]` | review the working-tree diff, fix, re-verify, re-review |
| `/pr <id>` | commit and open a **draft** PR via `pr.sh` |
| `/pr-self-check <pr> [--auto]` | review the PR, fix, push |
| `/pr-watch <pr>` | one tick — drive it with `/loop 15m` |
| `/review-pr <pr>` | review someone else's PR and post comments |
| `/ship <id\|"description">` | the stage machine that drives all of the above |
| `/manual-qa [id]` | drive the running app in a browser — **outside the loop**, human-triggered |

### The state file

`docs/plans/<ID>.state.json`, always in the **main checkout** — never
in a linked worktree, where `git worktree remove --force` would delete it.

| Field | Written by | Meaning |
|---|---|---|
| `taskId` | `plan-state.sh` | on first write |
| `stage` | each stage | `planned` → `implementing` → `verified` → `pr-open` → `self-checked` → `ready`, or `stopped` |
| `branchSlug` | `/plan-task` | the branch is built from it |
| `baseline.head` | `/ship` Stage 1 | the commit the run started from |
| `branchName`, `prNumber`, `prUrl`, `isDraft` | `pr.sh` | the PR handoff |
| `worktree` | `/ship` Stage 2a | the task worktree path |
| `verify.tier`, `verify.verdict` | `/implement-plan` | the last verification |
| `verify.backendAttempts` | `/verify-change` | cap counter for Backend — written **before** each attempt |
| `verify.testsAttempts` | `/verify-change` | cap counter for Tests — written **before** each attempt |
| `verify.frontendAttempts` | `/verify-change` | cap counter for Frontend — written **before** each attempt |
| `selfCheck.round` | `/pr-self-check` | cap counter, same rule |
| `qa.warranted`, `qa.what` | `/plan-task` | whether a browser pass is worth it |
| `stop.*` | any halt | `reason`, `stage`, `summary`, `report` |
| `report.path` | `/ship` Stage 5 | the run report |

`.claude/scripts/statusline.sh` renders the most recent one as a single line,
and goes quiet after six hours — the difference between an indicator and
furniture.

## Scripts

| Script | Contract |
|---|---|
| `verify.sh [tier] [scope] [workdir]` | prints a ` ```verify ` block last on stdout, exits 0/1. **The only thing allowed to decide.** |
| `plan-state.sh <id> <show\|path\|get\|set>` | JSON state in the main checkout; warns on an unknown field |
| `pr.sh <id> <slug> <message>` | the single choke point for a remote branch and a PR; always a draft |
| `statusline.sh` | one line, never blocks, always exits 0 |
| `qa-env.sh [--start]` | `VERDICT: READY\|BLOCKED`; starts services, **never seeds** |

### verify.sh tiers

| Tier | Runs |
|---|---|
| `quick` | compile + lint per changed area — the inner fix loop |
| `tests` | the backend suite alone, for the test writer's loop |
| `full` | everything but integration — before `/pr` and any push |
| `integration` | + suites needing external services; **never inside a retry loop** |

## Hooks

| Hook | Event | Enforces |
|---|---|---|
| `protect-plan-artifacts.sh` | PreToolUse · Bash | invariants 1, 2 and 5 |
| `protect-migrations.sh` | PreToolUse · Edit/Write | generated files stay generated |
| `protect-generated-files.sh` | PreToolUse · Edit/Write | generated files stay generated |
| `post-compact-reminder.sh` | SessionStart · compact | re-injects the rules and where the counters live |

`test-protect-plan-artifacts.sh` is the fixture for the first one. **Run it after
any edit to its patterns.** A PreToolUse hook that errors exits 2, which the
harness reads as *blocked* — so a broken guard is indistinguishable from a
working one until it blocks something you needed.

## Permissions

An unattended run needs an allowlist, and granting one is an explicit human act
— so the generator ships `settings.local.example.json` rather than writing
`settings.local.json` for you. Copy it, read every line, then keep it local.

Two absences in it are deliberate: bare `git push` and `gh pr create`. `pr.sh`
is the single choke point for both, and it only ever opens drafts. Granting the
underlying commands directly gives that away for nothing.
